How we measure tokens and cost

Every LLM call is measured the same way in both modes. The only difference is what goes into the call.

1

Tokens

tokens ≈ characters ÷ 4

Gemini's tokenizer averages about 4 characters per token for English and JSON. Every piece of text sent to or written by the model is measured this way.

2

Input, on every call

system + tools + request + conversation

The model has no memory between calls, so everything is sent again each time: the agent's role, the tool definitions, the request and earlier agents' handoffs, and the conversation so far.

3

Output

what the model writes

Tool-call requests (direct MCP), the script (code mode), summaries and the final answer. With direct MCP the Savings Calculator writes out its own working, one line per plan per month.

4

Cost

input × $0.375 / 1M + output × $1.88 / 1M

Gemini 3.8 Flash pricing per 1 million tokens, in US dollars, bought directly from Google. Output costs about 5× more than input.

Direct MCP: what grows

Every tool result is added to the conversation and sent again on every later call. After two half-year pages of daily usage for Deepan's three lines, about 115 KB of raw records sits in the conversation, so the Usage Analyst's last call alone carries about 31,000 input tokens.

Code mode: what stays small

Tool results stay inside the sandbox and are counted as KB, not tokens. Only the script's return value, usually 1–3 KB, joins the conversation.

Not included in these numbers

  • Thinking tokens: Gemini's internal reasoning, billed as output. It would add to both modes.
  • Caching discounts: Gemini can discount repeated input, which would lower direct MCP's real cost (not its token count).
  • Retries after errors or rate limits.
  • Time is modelled: 0.45 s per call + 0.04 ms per input token + 4 ms per output token + 160 ms per direct tool call (30 ms in the sandbox).
